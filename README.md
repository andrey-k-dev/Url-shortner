# URL Shortener

Сервис для сокращения ссылок на Spring Boot с асинхронным трекингом кликов через Kafka и кэшированием через Redis.

## Возможности

- Создание коротких ссылок из длинных URL
- Редирект по короткому коду с проверкой активности и срока действия ссылки
- Деактивация ссылок
- Асинхронный сбор статистики кликов (IP, User-Agent, Referer, время клика) через Kafka
- Статистика по ссылке: количество кликов, количество уникальных посетителей, дата первого и последнего клика, с опциональной фильтрацией по периоду
- Кэширование данных о ссылках в Redis для быстрого редиректа без обращения к БД на каждый запрос
- Миграции БД через Flyway
- Документация API через Swagger UI (springdoc-openapi)
- Мониторинг через Spring Boot Actuator

## Стек технологий

- **Java 17**
- **Spring Boot** (Web MVC, Data JPA, Validation, Actuator)
- **PostgreSQL** — основное хранилище данных
- **Flyway** — версионирование схемы БД
- **Apache Kafka** — асинхронная обработка событий кликов
- **Redis** — кэширование данных о ссылках
- **springdoc-openapi** — автогенерация Swagger-документации
- **Lombok**
- **Maven**

## Архитектура

```
Клиент
  │
  ├─ POST /api/v1/links              → создание короткой ссылки
  │
  ├─ GET  /{shortCode}                → редирект на оригинальный URL
  │        │
  │        ├─ проверка ссылки (кэш Redis → fallback в PostgreSQL)
  │        └─ событие клика отправляется в Kafka (асинхронно, не блокирует редирект)
  │                     │
  │                     ▼
  │            Kafka Consumer (батчами)
  │                     │
  │                     ▼
  │            PostgreSQL (click_event)
  │
  ├─ PATCH /api/v1/links/{shortCode}  → деактивация ссылки (с инвалидацией кэша)
  │
  └─ GET  /api/v1/stat/{shortCode}    → статистика кликов по ссылке
```

Редирект не ждёт записи клика в БД — событие публикуется в Kafka, а отдельный consumer сохраняет клики батчами в PostgreSQL. Это позволяет редиректу оставаться быстрым независимо от нагрузки на систему статистики.

## Требования

- JDK 17+
- Maven 3.9+
- Docker и Docker Compose (для локального запуска PostgreSQL, Kafka, Redis — само приложение в Docker запускать не обязательно, для разработки удобнее гонять его напрямую через `mvnw`/IDE)

## Быстрый старт

1. Клонируйте репозиторий:

```bash
git clone https://github.com/andrey-k-dev/Url-shortner.git
cd Url-shortner
```

2. Скопируйте `.env.example` в `.env` и при необходимости поправьте значения:

```bash
cp .env.example .env
```

3. Поднимите инфраструктуру (PostgreSQL, Redis, Kafka, Kafka UI):

```bash
docker compose up -d
```

Дождитесь, пока все сервисы перейдут в статус `healthy`:

```bash
docker ps
```

4. Передайте переменные окружения из `.env` в приложение — например, через Run Configuration в IntelliJ IDEA (Environment variables), либо экспортируйте их в терминале вручную, и запустите приложение:

```bash
./mvnw spring-boot:run
```

При старте Flyway автоматически применит миграции. Приложение поднимется на `http://localhost:8080`.

> Если поднимали `docker-compose.yml` раньше с другими значениями `POSTGRES_USER`/`POSTGRES_PASSWORD` — volume с данными БД мог создаться со старыми кредами. В этом случае пересоздайте его: `docker compose down -v && docker compose up -d`.

## API

После запуска Swagger UI доступен по адресу:

```
http://localhost:8080/swagger-ui.html
```

### Основные эндпоинты

| Метод | Путь | Описание |
|---|---|---|
| `POST` | `/api/v1/links` | Создать короткую ссылку |
| `GET` | `/{shortCode}` | Редирект на оригинальный URL |
| `PATCH` | `/api/v1/links/{shortCode}` | Деактивировать ссылку |
| `GET` | `/api/v1/stat/{shortCode}` | Получить статистику кликов (параметры `from`, `to` — опциональны, формат ISO-8601) |

Пример запроса статистики:

```
GET /api/v1/stat/vO7U2wc?from=2026-09-01T00:00:00&to=2026-09-18T23:59:59
```

Если `from`/`to` не переданы — фильтрация по времени не применяется, возвращается статистика за всё время.

## Обработка ошибок

Все ошибки возвращаются в едином формате через глобальный обработчик исключений:

```json
{
  "timestamp": "2026-09-18T15:07:24",
  "status": 400,
  "error": "Bad Request",
  "message": "Некорректный формат параметра 'from'",
  "path": "/api/v1/stat/vO7U2wc"
}
```

## Локальная отладка Kafka

После `docker compose up -d` поднимается веб-панель Kafka UI:

```
http://localhost:8081
```

Там можно посмотреть список топиков, реальные сообщения о кликах и состояние consumer group `click-persistence` (включая lag — сколько сообщений ещё не обработано). Топик создаётся автоматически при первой отправке события, вручную создавать его не нужно.
